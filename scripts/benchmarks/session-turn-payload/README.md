This probe measures the actual `persistCommittedTurn` path, including canonical
SQLite commits, durable window sources, receipts, and intent/catalog writes. It
does not call an encoder in place of the writer. Use the repository's pinned
Node and pnpm versions, a dedicated checkout, and the Node SQLite binding used
by the `session-main-db` Vitest project.

The synthetic conversation contains two turns. The image turn has 119 image
occurrences, 73 distinct byte strings, 47,244,868 inline base64 bytes and
29,165,512 distinct base64 bytes. These are structural measurements from the
issue; the generated bytes contain no private content and are not valid PNGs.
The second turn contains 1,277 execute results with 10,688,334 output text bytes;
each `rawOutput` contains exactly that item's output in `aggregatedOutput`.
Each turn receives three outcome/time revisions with unchanged bodies.

Run the identical harness at the baseline and candidate commits, alternating
their order across at least three fresh process pairs. Copy `probe.db.test.ts`
and `fixture.ts` together into a temporary directory under
`apps/desktop/electron/session/main/core/`, so the repository's existing DB
test project discovers them. Record the source SHA and the harness file hashes
separately, including any source archive hashes. Remove only that temporary
harness directory afterwards; do not edit either revision's product source.

Supply fresh absolute `GUGU_HOME`, `GUGU_USER_DATA_DIR`, and
`GUGU_SESSION_DB_FILE` values in the final process environment, as well as:

- `GUGU_TURN_BENCH_ROOT`: a new result directory beneath an existing private parent.
- `GUGU_TURN_BENCH_SHA`: the exact source commit.
- `GUGU_TURN_BENCH_MODE`: `before` or `after`.
- Preload this directory's `io-preload.cjs` using Node's `--require` option.

Invoke `pnpm exec vitest run --project session-main-db --no-file-parallelism`
with the copied probe's explicit path. Keep the caller's worker/resource
limits and watchdog active. This probe opens no app, engine, account, or user
database. It refuses to reuse a result directory and checks for 16 GiB free.

`result.json` includes every write sample, stage timings, actual WAL growth,
successful Node file-write bytes, read/sync counters, SQLite settings, and
verification results. WAL autocheckpoint is disabled in both runs so every
committed WAL frame contributes to monotonic file growth. Synchronous remains
FULL; migration/setup/checkpoint work is outside the measured interval.
Total written bytes are WAL growth plus measured Node file writes, including
temporary files and metadata. This describes bytes submitted through those
paths, not storage-device write amplification or directory-entry metadata.
The preload first verifies itself against the writer's sync and FileHandle
write routes. A failed sample is retained in `failure.json` and aborts the run.

Verification reopens the real database, compares the complete current history,
checks database integrity, and hashes every prior immutable window snapshot.
Report the raw samples and paired medians/ranges for initial inserts and small
revisions separately; do not describe three samples as a reliable tail latency.
